# Snipe-IT UI Automation

**C#, Playwright and NUnit** to automate tests on the [Snipe-IT demo website](https://demo.snipeitapp.com/).

## 1. Requirements

- Mac with Google Chrome installed
- .NET SDK required by the project (`net10.0`)
- Project cloned or downloaded from GitHub

## 2. Set Up the Project

Clone the GitHub repository:

git clone https://github.com/LozanY/QA-assessment-Global360.git

Navigate to the project directory:

cd QA-assessment-Global360/snipeIT-autoTests
```

Restore dependencies:

```bash
dotnet restore
```

Build the project:

```bash
dotnet build
```

## 3. Run the Tests

Run all tests:

```bash
dotnet test
```

Run only the login test:

```bash
dotnet test --filter "FullyQualifiedName~TC01_VerifyLogin"
```

Run only the asset creation test:

```bash
dotnet test --filter "FullyQualifiedName~CreateNewAsset"
```

Run the asset creation and validation tests together:

```bash
dotnet test --filter "FullyQualifiedName~AssetTests"
```

Run only the asset history test:

```bash
dotnet test --filter "FullyQualifiedName~VerifyAssetHistoryTests"
```

**Tip:** Some tests depend on an asset tag generated by the creation test. Run dependent tests together in the same test run.

## 4. Project Files

- `baseTest.cs` — opens and closes the browser for tests that inherit from it.
- `LoginTests.cs` — verifies that login works.
- `Pages/LoginPage.cs` — contains reusable login steps.
- `Tests/createAssetsTC.cs` — creates an asset and captures its asset tag.
- `Tests/validateAssestsTC.cs` — searches for the created asset and opens it.
- `Tests/verifyAssestTC.cs` — checks the asset's History tab.

## 5. Troubleshooting

- **Build fails:** Run `dotnet restore`, then `dotnet build`.
- **Asset not found:** Check the asset tag printed in the test output and search for it manually on the Snipe-IT website.
- **Test times out:** Check the error message, file name and line number.
- **Chrome does not open:** Check that Chrome is installed at the path configured in the test code.
